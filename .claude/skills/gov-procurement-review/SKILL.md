# 政府采购与企业采购文件合规排查

面向采购岗位人员的采购文件发布前合规初筛工具，覆盖国家法规 + 集团/公司内部制度双层依据。

## 一、定位与边界（必须向用户声明）

- 本工具是**发布前初筛**，不替代法律意见、不替代财政部门认定、不替代内部审计结论。
- 法规覆盖：中央层面现行有效的法律、行政法规、部门规章、规范性文件（已编译为规则库）。
- 内部制度覆盖：中国金融电子化集团有限公司（集团本部，G 口径）与金电信息科技（北京）有限责任公司（J 口径）现行采购制度，已摘录为 L4 规则层。
- **不覆盖**：地方集采目录与采购限额标准、行业特殊规定、事实判断类问题（如技术参数是否实质指向唯一供应商）、集团"三重一大"等上位决策制度细节。这些必须列入报告"待人工确认"。
- **内部制度判定不称"违法"**，统一表述为"违反公司/集团制度"，与国家法规问题分列。

## 二、判定铁律（违反则本次判定无效）

1. **禁止编造条款**。每条判定必须引用规则库/制度库中的原文摘录与条款号，禁止生成规则库以外的条款号或条文。内部制度引用格式：《制度全称》第 X 条（或附件 N）。
2. **存疑不判合规**。规则库未覆盖的可疑表述，一律标注"存疑"并说明疑点，不得判为"未发现问题"。
3. **数值比对须先定位**。涉及金额、比例、工作日的判定，必须先在原文件中定位到具体数值，再与规则阈值比对（如 10/50/200/300/500 万、3000 元、5 个工作日、30 日、10%）；未找到数值的，标注"未检索到，需人工确认"，不得默认合规。
4. **先分诊采购主体**。同一事项集团（G）与公司（J）阈值不同（如审批权限、预留周期、分散采购上限），须先确认采购主体再取口径；主体不明时两套口径并列提示并列入"待人工确认"。
5. **覆盖率必须声明**。报告须写明本次实际检查的规则条数与覆盖环节，以及未覆盖领域。
6. **不修改原文件**。只输出问题清单与建议表述，不直接改写用户的采购文件。

## 三、五步流程

### 第 1 步：解析与字段抽取

```
python scripts/extract_fields.py <采购文件.txt/docx>
```

优先用脚本抽取；若失败则人工阅读。必须抽齐以下字段，缺一项就在报告中标注"未检索到"：

| 字段 | 用途 |
|---|---|
| 采购主体（集团本部/金电信科/子公司） | 决定 L4 采用 G 或 J 口径 |
| 采购方式 | 决定加载 L1 哪一节 |
| 标的类型（货物/工程/服务） | 决定价格权重、适用法域 |
| 预算金额 / 最高限价 | 保证金上限、中小企业预留、异常低价阈值、L4 限额/审批档位 |
| 供应商资格条件 | L0 歧视性条款检查 + L4 禁入名单条件 |
| 技术参数与商务要求 | 是否指向特定品牌/供应商 |
| 评审方法与分值构成 | 最低评标价法 vs 综合评分法、价格权重 |
| 保证金（投标/履约） | 比例与形式 |
| 关键时限 | 公告期、提供期、投标截止、澄清期限、征集期、公示期 |
| 合同与验收条款 | 履约、付款、验收、续签与补充合同 |
| 审批与论证记录 | 内部审批层级、单一来源论证与公示、需求调查记录 |

### 第 2 步：项目画像分诊

- **工程类 + 采用招标方式** → 适用《招标投标法》体系（发改委 16 号令、10 号令、公平竞争审查规则）。本技能 L1 对此仅部分覆盖，**必须显式提示用户**：规则库以政府采购法体系为主，工程招标需另行核验。
- **货物/服务 + 公开招标（含邀请招标）** → 加载 L1「公开招标」节
- **竞争性谈判 / 询价 / 单一来源** → 加载 L1 对应节
- **竞争性磋商 / 框架协议 / 合作创新** → 加载 L1 对应节（基础覆盖）
- **内部采购方案 / 分散采购 / 单一来源论证材料** → 重点加载 L4（内部制度），国家法规仍作底线校验
- **采购主体分诊**：集团本部 → L4 取 G 口径；金电信科 → 取 J 口径；子公司 → G 制度第四十一条（子公司参照制定并备案）+ J 委托限额

### 第 3 步：分层加载规则

| 层级 | 文件 | 加载条件 |
|---|---|---|
| L0 | `references/rules/L0_redlines.md` | **每次必载** |
| L1 | `references/rules/L1_by_method.md` | 按采购方式加载对应节 |
| L2 | `references/rules/L2_by_policy.md` | 按触发条件加载（见文件内索引） |
| L3 | — | 地方集采目录、限额标准、公开招标数额标准，**向用户索取地区+年度**；未取得时列"待人工确认" |
| L4 | `references/rules/L4_internal_policies.md` | **每次必载**（按采购主体取 G/J 对应条款；制度原文在 `references/policies/`，需复核时查阅） |

### 第 4 步：逐条判定

按严重度定性：

- **A 违法**：可致投诉成立、行政处罚或采购结果无效。必须整改后才能发布。
- **A 违反内部制度**：不直接违法，但违反集团/公司强制条款（如化整为零、超限额未集采、论证公示缺失），内部审计/纪检监督将追责。必须整改。
- **B 瑕疵**：程序不当，易被质疑或影响采购效率。建议整改。
- **C 建议**：表述可优化，非强制。

判定顺序：先 L0 红线（一票否决项），再 L1 方式与程序，再 L2 政策功能，最后 L4 内部制度（限额、审批、论证公示、验收、岗位分离）。

### 第 5 步：输出报告

按 `references/templates/report.md` 结构输出（国家法规问题与内部制度问题分列，附覆盖率声明）。可调用：

```
python scripts/render_report.py --input findings.json --output 排查报告.md
```

## 四、常见误判防范

- **"没有写"不等于"违规"**：部分要求是"应当载明"，缺失才违规；部分要求是对行为的限制。判定前先看清规则是"禁止性"还是"必备要素"。
- **区分"应当"与"可以"**：规则中标注为"可以"的，缺失不构成违规，只能给 C 级建议。
- **新法与旧法**：现行《政府采购法》仍为 2002 年通过、**2014 年修正版**；修订草案 2026 年 6 月仅提请初审，**不得作为依据**。
- **新制与旧制**：内部制度以现行版为准——G 口径 2024-08-05 施行（废止金电字〔2022〕23 号试行版）；J 口径采购管理规定 2025-05-21 施行、分散采购/供应商/单一来源细则 2025-05-14 施行（废止金电信科字〔2024〕24 号）。引用旧版条文视为错误。
- **叠加适用**：中小企业政策需叠加财库〔2020〕46 号、〔2022〕19 号、财预〔2023〕76 号、国办发〔2024〕33 号，按最新口径执行。
- **两套口径冲突**：J 口径严于 G 口径时（如分散采购 3000 元审批线、10-50 万集采区间），按项目所属主体执行，报告中并列标注另一口径以供参考。

## 五、维护

每条规则带 `source`（文件+条款）、`effective_date`。法规或内部制度更新时，按 `source` 回溯复核受影响规则。规则库版本见本文件 frontmatter 的 `version`；`rules.json` 由 `scripts/export_rules.py` 编译生成，**改规则后须重跑**。

内部制度更新流程：新版制度 PDF 放入 `references/policies/_source/` → 转换为 md（`scripts/convert_policies.py`）→ 人工校对 `references/policies/` 下 md → 更新 `L4_internal_policies.md` 对应条款 → 重跑 `export_rules.py`。
