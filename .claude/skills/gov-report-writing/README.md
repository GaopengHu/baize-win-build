## 简介

`gov-report-writing`（中文名：公文写作）是一个专为国央企和党政机关公文写作场景设计的 WorkBuddy Skill。它内置了 GB/T 9704-2012 国标公文格式规范（含企业级扩展）、31+ 种模板框架（8 类工作模板 + 7 种行政公文 + 11 种专题模板 + 信函式文件 + 应急预案/议程/慰问信/专项总结/联合行文）、公文专用措辞词汇库，以及**五维 100 分质量评分**（合规/完整/规范/准确/文风），能够将一份标准公文从"调格式 + 写内容 + 润色 + 质检"的 2 小时工作压缩到几分钟。

## 核心功能

| 功能 | 说明 |
|------|------|
| 📐 国标排版 | 严格遵循 GB/T 9704-2012，自动设置页边距、字体、字号、行距、层级标题格式 |
| 📋 31+ 种模板 | 8类工作模板 + 7种行政公文 + 11种专题模板 + 信函式文件 + 应急预案/议程/慰问信/专项总结/联合行文 |
| ✍️ 公文用语 | 内置政治术语校验、口语→公文替换规则、常用句式库 |
| 📊 质量评分 | 五维 100 分自动评分（合规30/完整25/规范20/准确15/文风10），输出问题清单与改进建议 |
| 🔒 安全红线 | 执行前自动识别敏感信号，占位符机制保护敏感信息 |

## 安全特性

- 执行前自动检测涉密信号（密级标注、项目代号、技术参数）

- 全程本地处理，不上传云端
- 每份输出文档附带安全提示

## 能力边界说明

本 Skill 擅长与不擅长的事项明确如下，便于合理预期。**详细能力边界矩阵、失败案例库与协作工具版本清单见 [`references/capability-matrix.md`](references/capability-matrix.md)**。

**✅ 擅长**
- 中文公文/报告的框架搭建、内容生成、措辞优化、格式排版
- 国央企、党政机关、事业单位 31+ 类文书模板（8 类工作 + 7 类行政 + 11 类专题 + 信函/应急预案/议程/慰问信/专项总结/联合行文）
- GB/T 9704-2012 国标排版（页边距/字体/行距/层级序号）
- 风格仿写（基于往年材料提取写作风格后生成新稿）
- 篇章级润色（语病/句式/过渡/数据一致性四层检查）

**⚠️ 有限支持**
- PDF 输出：生成 Word 后需配合 PDF 转换工具
- 图片/扫描件/语音素材：需先转为文字后才能处理
- 特殊字体：系统缺字体会正常设置字体名，但显示需自行安装
- 31+ 类同时生成：单类质量高，跨类有压力，建议拆分任务

**❌ 不支持**
- 涉密内容：遇到密级标注、项目代号等信号会拒绝处理（需脱敏后使用）
- 英文公文：仅支持中文公文写作
- 法律文书/合同起草：建议使用专业法律工具
- 编造政策内容：涉及具体政策文件时用占位符提示，不自行虚构
- 伪造红头/公章：涉及真实性问题，需使用单位正式模板

## 常见问题

**Q: 生成的文档字体不对？**
A: 请确认系统已安装仿宋_GB2312、楷体_GB2312 和方正小标宋简体。可从 Windows 字体库或 WPS 安装目录获取。

**Q: 能否处理涉密文件？**
A: 不能。本 Skill 内置安全检测机制，遇到涉密信号会自动拒绝处理。请将文档脱敏后再使用。

**Q: 支持 PDF 输出吗？**
A: 当前默认输出 Word (.docx)，可配合 WorkBuddy 的 PDF 转换功能导出为 PDF。

**Q: 怎么触发这个 Skill？**
A: 在 WorkBuddy 中直接说需求即可自动触发，如"帮我写一份年度工作总结""按公文格式写个请示"。也可以说"用公文写作技能写……"显式指定。

**Q: 能处理 5000 字以上的长报告吗？**
A: 可以。超过 5000 字会自动启动分段生成策略：先生成大纲→逐章写作→每章确认→全文统稿，保证长文质量和上下文一致性。

**Q: 有没有参考范文？**
A: 有。`references/case-examples.md` 收录了 HR/财务/党建/安全/科研五条线的范文片段和专业点评，生成前可参考。

**Q: 格式检查脚本怎么用？**
A: 生成 Word 后可运行 `python scripts/format_check.py <文件路径>` 自动检查页边距/字体/行距/层级序号，支持 `--json` 和 `--quiet` 参数。

**Q: 想按往年材料的风格写怎么办？**
A: 上传一份往年材料，说明"按这个风格写"，Skill 会提取标题风格、用词偏好、语气基调等特征后按同风格生成新稿。

**Q: 生成时遇到错误或失败怎么办？**
A: 本 Skill 内置 8 类错误处理机制（E1-E8），覆盖字体缺失、文件损坏、上下文过长、生成失败、越界、并发、模糊请求、恶意输入。失败时会自动重试 1-2 次，无法恢复则输出 Markdown 降级版本。

**Q: 怎么处理用户提的模糊需求？**
A: 例如"帮我写个报告"这种类型不明的请求，Skill 会先列出 3-4 个最可能类型供你选择，再询问部门、字数、时间范围，不会擅自决定关键要素。

**Q: 怎么给写好的公文打分？**
A: 运行 `python scripts/quality_score.py <文件路径>`，会按五维 100 分制（合规 30 / 完整 25 / 规范 20 / 准确 15 / 文风 10）评分，并输出问题清单和改进建议。支持 .docx / .md / .txt；用 `--type <类型>` 指定报告类型可提高章节校验准确度；草稿用 `--draft` 跳过占位符检查；程序化调用用 `--json`。90 分以上为 A 档可直接提交。评分标准详见 `references/quality-scoring.md`。

**Q: 质量评分和格式检查脚本有什么区别？**
A: 两者检查的层面不同，建议串联执行：`format_check.py` 管 **DOCX 排版层**（页边距、字体、行距、缩进、页码）；`quality_score.py` 管 **文本内容层**（政治术语、信息充分性、数据一致性、AI 痕迹等）。前者保证"长得像公文"，后者保证"内容够格"。
