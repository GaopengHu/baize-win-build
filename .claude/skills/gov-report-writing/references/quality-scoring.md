# 公文质量评分标准（Quality Scoring Standard）

> 版本：v1.6.0 新增 | 配套脚本：`scripts/quality_score.py`
> 对标短板：**E 有效性·信息充分性**、**C 规范性·叙述式描述**

---

## 一、这份文档解决什么问题

本 Skill 已有的 `references/vocabulary-guide.md` 第七章收录了 52 项表述问题检查清单，但它是**被动扫描清单**——只有在生成后逐条对照时才有意义，无法回答两个关键问题：

1. 这篇公文**整体好不好**？
2. 如果不好，**先改哪里**收益最大？

本文档把 52 项清单升级为**可量化的评分标尺**：五维 100 分制，每个维度有明确的判定细则、扣分标准和修复建议。脚本 `quality_score.py` 依据本标准自动执行，输出分数 + 问题清单 + 改进建议。

### 与 format_check.py 的分工

| 脚本 | 检查层 | 检查内容 | 对标维度 | 典型问题 |
|------|--------|---------|:---:|---------|
| `format_check.py` | **DOCX 排版层** | 页边距、字体字号、行距、缩进、页码、层级序号 | C 规范性 | "标题字体应为方正小标宋简体" |
| `quality_score.py` | **文本内容层** | 合规、完整、规范、准确、文风 | **E 有效性** | "第 3 段'搞'应改为'开展'" |

两者互补不重叠，建议串联执行：**先跑 format_check 验排版，再跑 quality_score 验内容**。

## 二、评分体系总览

| 维度 | 权重 | 核心关切 | 一票否决项 |
|------|:---:|---------|:----------|
| **合规度 Compliance** | **30** | 政治术语、机构名称、禁用词是否违规 | 政治术语错误（可扣至负分） |
| **完整度 Completeness** | **25** | 结构要素是否齐全、信息是否充分 | — |
| **规范度 Convention** | **20** | 序号、数字、标点、引用是否符合规范 | — |
| **准确度 Accuracy** | **15** | 数据是否前后一致、单位是否统一 | — |
| **文风度 Style** | **10** | AI 痕迹、小标题对仗、句式节奏 | — |
| **合计** | **100** | | |

**权重设计依据**：合规度权重最高（30），因为公文的政治性错误是"一票否决级"问题，后果远重于其他瑕疵；完整度次之（25），直接对应 E 有效性中"信息充分性"这一核心子项；规范度、准确度再次；文风度权重最低（10），因其属锦上添花项，且部分（如句式节奏）难以完全自动化判定。

## 三、维度一：合规度（30 分）

> 判定依据：`references/vocabulary-guide.md` 第七章 52 项检查清单中的硬性违禁项

### 3.1 政治术语错误（15 分，每项 -5，可扣至负分）

公文中政治表述错误属**最高优先级问题**，采用重罚机制，可突破本维度分值下限。

| 序号 | 错误表述 | 正确表述 |
|:---:|---------|---------|
| 1 | 四个意识、四个自信（顺序错） | 增强"四个意识"、坚定"四个自信"、做到"两个维护" |
| 2 | 二十大精神（缺"党"） | 党的二十大精神 |
| 3 | 高速增长 | 高质量发展 |
| 4 | 中国式现代化（缺"全面"） | 以中国式现代化全面推进中华民族伟大复兴 |
| 5 | 全国人大（首次出现） | 全国人民代表大会 |
| 6 | 全国政协（首次出现） | 中国人民政治协商会议全国委员会 |
| 7 | 纪委（首次出现） | 中共中央纪律检查委员会 |
| 8 | 监察委 | 国家监察委员会 |

**判定说明**：序号 5-7 仅在"首次出现未用全称"时扣分，后续使用规范简称不扣分。

### 3.2 机构名称不规范（5 分，每项 -2）

| 序号 | 易错点 | 规范 |
|:---:|--------|------|
| 9 | 单位全称首次出现未写全称 | 首次必须使用全称，括号注明"以下简称 XX" |
| 10 | 部门名称不完整 | 除通用简称外，使用完整部门名称 |
| 11 | 上级单位称谓不统一 | 全文保持统一称谓 |

### 3.3 禁用词（8 分，每项 -1）

| 类别 | 禁用词 | 建议替代 |
|------|--------|---------|
| 口语化 | 搞、弄、做、干、整 | 开展、办理、实施、推进、处理 |
| 绝对化 | 完全、绝对、100% | 基本、较为、全面、显著 |
| 夸张修辞 | 史无前例、前所未有、极大 | 删除，用事实和数据说话 |
| 情绪化 | 非常、特别、极其 | 删除程度助词 |
| 模糊表述 | 大概、可能、好像、差不多 | 删除或替换为具体数据 |

**判定说明**：共 21 个禁用词。脚本按词表逐词扫描，命中即扣 1 分，同类多次命中累计扣分。

### 3.4 占位符未替换（2 分，每处 -0.5）

检测 `XX`、`XX%`、`XXXX年` 等占位符在成稿中未替换为实际值的情况。

**判定说明**：草稿阶段使用占位符属正常，此项主要针对**定稿检查**。若用户明确表示"这是草稿"，可用 `--draft` 参数跳过此项。

### 3.5 涉密信号处理（特殊规则）

> **重要**：涉密信号**不采用一票否决**，而采用「严重警告 + 总分扣 50 分」。

**为什么不一票否决**：部分单位名称天然含敏感词（如"某某研究所""某军工集团下属民品公司"），直接判 0 分会造成大量误伤，反而降低工具可信度。改为重扣分后，既能强力警示，又保留了人工复核空间。

| 信号类型 | 处置 |
|---------|------|
| 密级标注（绝密/机密/秘密） | ⛔ 严重警告 + 扣 50 分 |
| 文件编号含"密"字样 | ⛔ 严重警告 + 扣 50 分 |
| 军工项目代号、武器型号 | ⛔ 严重警告 + 扣 50 分 |
| 未公开的组织架构或编制信息 | ⛔ 严重警告 + 扣 50 分 |
| 具体技术参数、经费数据 | ⛔ 严重警告 + 扣 50 分 |

命中涉密信号时，报告顶部强制显示：

```
⛔⚠️ 严重警告：检测到疑似涉密信号，已扣 50 分
   请确认文档是否已脱敏。如确认可公开，可忽略本提示。
   如涉及涉密内容，请立即停止使用并按单位保密规定处理。
```

## 四、维度二：完整度（25 分）🎯

> 本维度是对标「E 有效性·信息充分性」的核心，权重 25%

### 4.1 必备要素齐全（12 分，6 项 × 2 分）

| 要素 | 判定方式 |
|------|---------|
| 标题 | 存在独立标题行，且非空 |
| 主送机关 | 存在"XX："形式的受文对象（信函/纪要类可豁免） |
| 正文 | 正文主体不少于 100 字 |
| 发文机关署名 | 文末存在发文单位名称 |
| 成文日期 | 存在完整日期（YYYY年M月D日） |
| 印章 | 存在"（印章）"标注或印章位置占位 |

**豁免规则**：会议纪要、会议议程、心得体会、党课讲稿等文种不强制要求"主送机关"；纯内容草稿（.md/.txt）不强制要求"印章"。

### 4.2 类型专属章节（8 分，缺一章 -2）

按报告类型校验核心章节是否齐备。脚本自动识别类型，置信度低时提示用户用 `--type` 手动指定。

| 报告类型 | 必备章节 |
|---------|---------|
| **年度工作总结** | 主要工作及成效 / 重点工作亮点 / 存在的问题与不足 / 下一步工作计划 |
| **述职报告** | 履职情况 / 工作亮点与创新 / 问题与不足 / 改进措施与努力方向 |
| **党建/思政报告** | 主要工作开展情况 / 存在问题 / 下一步工作思路 |
| **调研报告** | 调研背景与目的 / 现状分析 / 存在的问题及原因分析 / 对策建议 |
| **工作方案** | 总体要求 / 主要任务 / 实施步骤 / 责任分工 / 保障措施 |
| **整改方案** | 整改目标 / 整改任务及分工 / 整改步骤 / 保障措施 |
| **会议纪要** | 会议要素（时间/地点/主持人/出席人/记录人）+ 会议议题 / 会议内容 / 决议事项 |
| **通知/公告** | 事由 / 具体内容 / 要求（+ 时间、地点、对象三要素） |
| **请示** | 缘由 / 事项 / 结语 + 签发人 |
| **整改/巡视汇报** | 基本情况 / 主要做法及成效 / 存在问题 / 下步打算 |

**判定方式**：按章节关键词做模糊匹配（如"下一步工作计划"可匹配"下步打算""下步工作思路"等变体），避免因标题措辞差异误判。

### 4.3 信息密度（5 分，5 项 × 1 分）⭐

> 这是破解"信息不充分"的关键设计。公文内容空泛的五个典型症状，逐项检测：

| 指标 | 判定方式 | 缺失时的典型表现 |
|------|---------|----------------|
| **有数据支撑** | 存在百分比（X%）、绝对数（X万元/X人次）、同比（增长X%） | 通篇"成效明显""大幅提升"，无一个数字 |
| **有具体事例** | 存在具体事件/项目/人名/地点描述 | 泛泛而谈"加强管理""优化流程"，无实例 |
| **有责任分工** | 存在"XX部牵头""责任人：XX"等表述 | 措施无主，找不到谁负责 |
| **有时间节点** | 存在"X月X日前""2025年底前""每季度"等时限 | 计划无期限，无法考核 |
| **有量化成效** | 成效部分含量化结果（完成率/达标率/增长率） | 只说"完成了工作"，不说完成到什么程度 |

**典型病例对照**：

| ❌ 信息不充分（扣分） | ✅ 信息充分（满分） |
|---------------------|-------------------|
| "今年以来，我部大力推进降本增效工作，取得明显成效。" | "今年以来，我部推进降本增效，累计节约采购成本 1,240 万元，同比下降 18.6%，超额完成年度目标（1,000 万元）124%。" |
| "下一步将继续加强人才队伍建设。" | "下一步由人力资源部牵头，9月底前完成第二批技术骨干招聘（30 人），四季度组织专项培训 4 场，覆盖率达 95% 以上。" |

## 五、维度三：规范度（20 分）

> 判定依据：`references/vocabulary-guide.md` 第六章「格式与排版微操」

### 5.1 层级序号格式（5 分）

标准四级序列：**一、** → **（一）** → **1.** → **（1）**

| 检查项 | 扣分 |
|--------|:---:|
| 用点号代替顿号（"一." 应为 "一、"） | -2 |
| 括号层级加标点（"（一）、" 应为 "（一）"） | -2 |
| 层级跳级（一、后直接 1. ） | -1 |
| 中英序号混用 | -1 |

### 5.2 数字用法（4 分）

| 检查项 | 扣分 |
|--------|:---:|
| 年份未用全称（"25年" 应为 "2025年"） | -2 |
| 日期格式错误（"2025-7-24" 应为 "2025年7月24日"） | -1 |
| 概数用阿拉伯数字（"35天" 应为 "三五天"） | -1 |
| 序号编虚位（"01号" 应为 "1号"） | -1 |

### 5.3 标点符号（4 分）

| 检查项 | 扣分 |
|--------|:---:|
| 年份括号用方括号（"[2025]" 应为 "〔2025〕"） | -2 |
| 标题含标点符号（除法规名称书名号外） | -1 |
| 附件名称后加句号 | -1 |
| 多个附件序号未对齐 | -1 |

### 5.4 引用规范（4 分）

| 检查项 | 扣分 |
|--------|:---:|
| 引用公文未先引标题后引发文字号 | -2 |
| 法律法规未用全称 | -1 |
| 疑似编造政策文件（无发文字号且无"精神/要求"等缓冲表述） | -2 |

### 5.5 公文规范（3 分）

| 检查项 | 扣分 |
|--------|:---:|
| 请示非一事一请 | -1 |
| 报告夹带请示事项 | -2 |
| 上行文未标注签发人 | -1 |
| 主送/抄送单位名称不规范 | -1 |

## 六、维度四：准确度（15 分）

> 判定依据：`references/polishing-guide.md` 第四层「数据一致性检查」

### 6.1 数据前后一致性（5 分）

同一指标在文中多处出现时，数值必须一致。

| 检查项 | 扣分 |
|--------|:---:|
| 同一指标多处数值不一致 | -3/处 |
| 同一指标单位不同（前文"万元"后文"亿元"） | -2 |

**检测方式**：提取"指标名 + 数值"组合（如"营收 5 亿"），比对同名指标的所有出现。

### 6.2 分项加总校验（4 分）

分项之和应等于总数。

| 检查项 | 扣分 |
|--------|:---:|
| 分项之和 ≠ 总数（误差 > 1%） | -4 |
| 分项缺失（只给总数无分项） | -1 |

**示例**：三个部门人数分别为 120、85、95，总计应为 300。若文中写"总计 320"则判定不一致。

### 6.3 单位统一（3 分）

| 检查项 | 扣分 |
|--------|:---:|
| 同类数据单位混用（万元/亿元、%/个百分点、人次/人） | -1/处 |
| 数值单位缺失（"增长 20" 未说明是 % 还是万元） | -1 |

### 6.4 时间表述一致（3 分）

| 检查项 | 扣分 |
|--------|:---:|
| 年份写法不统一（"2025年" 与 "25年" 混用） | -1 |
| 时间口径冲突（前文"上半年"后文"前三季度"指同一事项） | -2 |
| 时间逻辑错误（"截止目前"数据却含未来时段） | -2 |

## 七、维度五：文风度（10 分）

> 判定依据：`references/ai-traces.md` 12 类 AI 痕迹检测规则

### 7.1 AI 痕迹检测（4 分）

按 12 类 AI 痕迹模式扫描，命中即扣分。

| 典型 AI 痕迹 | 扣分 |
|-------------|:---:|
| 破折号滥用（——） | -1 |
| "首先/其次/最后"机械三段式 | -1 |
| "值得注意的是""需要指出的是"等套语 | -0.5 |
| 过度排比（连续 4 组以上） | -1 |
| 空洞总结句（"总之""综上所述"+ 无实质内容） | -0.5 |
| emoji 混入正文 | -1 |

### 7.2 小标题对仗（3 分）

| 检查项 | 扣分 |
|--------|:---:|
| 同级标题字数差异 > 2 字 | -1 |
| 同级标题结构不一致（动宾/名词混用） | -1 |
| 标题层级不连续 | -1 |

**示例**：

| ❌ 不对仗 | ✅ 对仗 |
|----------|--------|
| 一、强化理论学习<br>二、业务工作推进情况<br>三、抓好团队建设 | 一、强化理论武装<br>二、推进业务发展<br>三、夯实团队基础 |

### 7.3 句式节奏（3 分）

| 检查项 | 扣分 |
|--------|:---:|
| 长句占比过高（单句 > 80 字占比 > 30%） | -1 |
| 被动句占比过高（ > 20%） | -1 |
| 排比组数过多（ > 3 组） | -1 |

## 八、分档标准

| 总分 | 评级 | 标识 | 判定 | 处置建议 |
|:---:|:---:|:---:|:---:|---------|
| 90-100 | **A 优秀** | 🟢 | 可直接提交 | 无需修改 |
| 80-89 | **B 良好** | 🔵 | 小修后可提交 | 修复 ≤3 处问题 |
| 70-79 | **C 合格** | 🟡 | 需修改后复审 | 按问题清单逐项修复 |
| 60-69 | **D 待改进** | 🟠 | 较大修改 | 建议重写部分章节 |
| < 60 | **E 不合格** | 🔴 | 重写 | 按模板重新生成 |
| 涉密命中 | **⚠️ 涉密待核** | ⛔ | 强制提示 | 总分扣 50 后按上述分档，但顶部强制显示警告 |

**分档设计说明**：80 分设为"良好"门槛，因为公文的容错率极低——一份有 2-3 处用词问题的公文，在体制内场景已属需要返工的范畴。90 分以上才代表"可直接提交"。

## 九、典型评分案例

### 案例一：信息不充分的年度总结（典型 E 扣分项）

**原文片段**：
> 今年以来，我部大力推进各项工作，取得明显成效。一是加强管理，提升了效率。二是优化流程，提高了质量。三是强化队伍，增强了能力。下一步，我部将继续努力，争取更大成绩。

**评分**：
- 合规度 28/30（"推进""加强"用词规范，无禁用词）
- **完整度 14/25**（必备要素齐全拿满 12 分；四章结构齐全拿满 8 分；**信息密度 0/5**——无数据、无事例、无责任、无时限、无量化成效）
- 规范度 18/20
- 准确度 15/15
- 文风度 7/10（"一是…二是…三是"机械三段式，空洞总结句）
- **总分 82 → 但完整度严重偏科**

**改进建议**：补充数据（如"效率提升 X%"）、事例（具体项目）、责任（XX 牵头）、时限（X 月底前）、量化成效（完成率 X%）。预计修复后完整度可达 23 分，总分 90+。

### 案例二：政治术语错误（合规度重罚）

**原文片段**：
> 我们深入学习二十大精神，坚持高速增长理念……

**评分**：
- **合规度 15/30**（"二十大精神"缺"党" -5；"高速增长"应为"高质量发展" -5；占位符无；禁用词无 → 30-10=20，但政治术语可扣至负分，此处扣 10 后为 20，另"我们"口语化 -1 → 19）
- 完整度 22/25
- 规范度 19/20
- 准确度 15/15
- 文风度 8/10
- **总分 83/100，但顶部强制标注「⚠️ 政治术语错误 2 处，必须修正后才能提交」**

**关键**：政治术语错误即使总分仍在 B 档，也**必须修复**——这是合规红线，不适用"小修后提交"的宽松判定。

### 案例三：涉密信号（扣 50 分，非一票否决）

**原文片段**：
> 根据《XX 装备 2025 年保障方案》（机密），我部完成……（单位名称：中国兵器工业集团 XX 研究所）

**评分**：
- 合规度 30/30
- 完整度 24/25
- 规范度 20/20
- 准确度 15/15
- 文风度 10/10
- 小计 99/100 → **涉密信号命中，扣 50 分 → 最终 49/100（E 档）**
- 顶部显示 ⛔ 严重警告

**关键**：即使用户单位名含"研究所"造成误伤（本例中"机密"标注才是真信号），扣 50 分后仍有 49 分，用户可看到具体命中项并判断是否为误报，而非被直接判 0 分导致工具不可用。

## 十、使用建议

### 在 Skill 工作流中的位置

```
阶段三：交付
  步骤 5  自检清单（8 项）
  步骤 5b 篇章级润色（>500 字）
  步骤 5c 质量评分（可选，推荐）  ← 本标准的执行位置
  步骤 6  输出 + 安全提示
```

### 推荐执行时机

1. **初稿完成后**：跑一次，看总分和问题清单，按优先级修复
2. **修改后复跑**：验证分数是否提升（脚本会显示"修复后预计可达 X 分"）
3. **定稿前终检**：确认 ≥ 90 分（A 档）再提交

### 命令行用法

```bash
# 基础用法（自动识别报告类型）
python scripts/quality_score.py 年度总结.docx

# 指定报告类型（提高章节校验准确度）
python scripts/quality_score.py 年度总结.docx --type 年度工作总结

# 草稿模式（跳过占位符检查）
python scripts/quality_score.py draft.md --draft

# 程序化调用
python scripts/quality_score.py 年度总结.docx --json

# 仅看问题项
python scripts/quality_score.py 年度总结.docx --quiet

# 输出全部检查项明细
python scripts/quality_score.py 年度总结.docx --verbose
```

### 分数不理想时的修复优先级

1. **先修合规度**（政治术语、机构名）——红线问题，无论总分多少都必须修
2. **再修完整度中的信息密度**——补充数据/事例/责任/时限/量化成效，这是提分最快的一项（满分 5 分，通常 0 分起步）
3. **再修准确度的数据不一致**——公文数据错误后果严重
4. **最后修文风度**——锦上添花，且部分项（句式节奏）自动化判定存在误差，人工判断优先
